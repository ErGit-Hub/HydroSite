# KazHydro — сайт НАО «НГС Казгидрогеология»

Одностраничное приложение (SPA) на Angular 21 для Национальной гидрогеологической
службы Республики Казахстан: информация о предприятии, направления деятельности,
проекты, новости, вакансии и антикоррупционный блок.

Интерфейс мультиязычный: русский (по умолчанию), казахский и английский.

## Требования

- Node.js 20.19+, 22.12+ или 24+ (`engines` у Angular 21; нечётные
  релизы — 21.x, 23.x — не поддерживаются)
- npm 10+

## Запуск

```bash
npm install
npm start          # dev-сервер на http://localhost:4200
```

Остальные команды:

```bash
npm run build      # продакшн-сборка в dist/hydro-site/browser
npm run build:dev  # сборка без минификации, с source maps
npm run watch      # пересборка при изменениях
npm test           # юнит-тесты (vitest)
npm run smoke      # прогон по живому приложению в headless-браузере
```

| `/security` | Служба информационной безопасности и ТБ |
| `/news`, `/news/:id` | Новости и карточка новости |
| `/404`, `**` | Страница 404 |

Все разделы подгружаются отдельными чанками (`loadComponent`). Исключение —
`/home`: её открывает каждый посетитель, поэтому она собрана в начальный бандл.
Остальные чанки докачиваются в фоне (`withPreloading(PreloadAllModules)`), так что
клик по меню не ждёт сети.

Заголовок вкладки задаётся полем `title` маршрута; `PageTitleStrategy`
(`src/app/core/page-title.strategy.ts`) добавляет к нему название сайта.

Маршрут `/404` нужен для страниц, у которых совпал путь, но не нашлись данные:
`news/:id` с несуществующим id уходит на него сам (`**` в этом случае не
срабатывает — путь-то совпал).

## Локализация

Переводы лежат в `src/assets/i18n/<lang>.json` и загружаются по HTTP через
`CustomTranslateLoader` (`src/app/core/translate.loader.ts`).

Загрузчик добавляет к адресу версию сборки: `assets/i18n/ru.json?v=FB6NZV3G`.
Хэш берётся из имени `main-*.js` в самом документе, поэтому отдельный счётчик
вести не нужно — новая сборка меняет его сама. Без этого браузер имеет полное
право отдать переводы из кэша после выкладки и показать вместо текста сами
ключи (`SECURITY.TITLE`): у файлов постоянный адрес, в отличие от скриптов с
хэшем в имени. Так и случилось в Safari 2026-09-03 — он держался за копию,
скачанную до того, как на сервере появился `.htaccess` с `no-cache`.

Активный язык — целиком зона ответственности `LanguageService`
(`src/app/core/language.service.ts`): он восстанавливает выбор из `localStorage`
при старте (`provideAppInitializer` в `app.config.ts`), откатывается на `ru`,
сохраняет каждое переключение и проставляет `lang` у `<html>`. Не задавайте язык
через `TranslateService.use` мимо сервиса — иначе выбор не сохранится, а `<html
lang>` разъедется с содержимым.

Список языков объявлен там же, в `LANGUAGES`; чтобы добавить язык, достаточно
дописать строку и положить рядом `<code>.json`. Сам выбор — в
`LangSwitcherComponent` (`src/app/components/lang-switcher/`): выпадающий список,
открывается по клику, закрывается по `Esc` и клику снаружи, стрелки водят по
пунктам. На десктопе он в шапке, на экранах ≤768px — внутри мобильного меню.

Чтобы добавить строку, внесите ключ во все три файла (`ru.json`, `kz.json`,
`en.json`) и используйте его в шаблоне: `{{ 'SECTION.KEY' | translate }}`.

Интерфейс полностью выведен в ключи: шапка, подвал и все страницы разделов
используют `| translate`. Тексты карточек проектов, должности руководства и
графики приёма тоже лежат в i18n — компоненты хранят только ключ (`PROJECTS.ITEMS.<key>`,
`LEADERS.<key>.POSITION`).

> `ru.json` и `en.json` совпадают ключ в ключ. `kz.json` заполнен частично —
> недостающее подставляется из `ru.json` по `fallbackLang`.

### Статус казахского

`kz.json` собран из двух источников, и это важно при правках:

| Раздел | Откуда текст |
| --- | --- |
| `RECEPTION`, `LEADERS`, `CONTACTS.ADDRESS` | официальные формулировки заказчика |
| `OMBUDSMAN` — должность, `ABOUT_1`, `ABOUT_2`, `NAME` | официальные формулировки заказчика |
| `ANTI_CORRUPTION` — офицер, `HOTLINE_*`, `INFO_*` | официальные формулировки заказчика |
| `ANTI_CORRUPTION.TITLE`, `SUBTITLE`, `DOCS_TITLE`, `DOCS_SUBTITLE` | **черновик, нужна вычитка** |
| `SECURITY` целиком и `HEADER.SECURITY` | **черновик, нужна вычитка** |
| `OMBUDSMAN.SUBTITLE`, `ABOUT_TITLE`, `DOC_TITLE`, `DOC_LINK` | **черновик, нужна вычитка** |
| `HEADER`, `FOOTER`, `HERO`, `NEWS`, `STRUCTURE`, `VACANCIES`, `CONTACTS` (кроме адреса) | **черновик, нужна вычитка** |

Разделы с содержательными текстами — `ABOUT`, `ABOUT_DETAILS`, `ACTIVITIES`,
`GOV`, `SERVICES`, `PROJECTS`, `ANTI_CORRUPTION`, `FEATURES`, `AUDIENCE`,
`ADVANTAGES`, `MODULES` — на казахский ещё не переводились и показываются
по-русски через фолбэк.

Сверить покрытие:

```bash
node -e "const r=require('./src/assets/i18n/ru.json'),k=require('./src/assets/i18n/kz.json');
const f=(o,p='')=>Object.entries(o).flatMap(([a,b])=>typeof b==='object'&&!Array.isArray(b)?f(b,p+a+'.'):[p+a]);
const m=f(r).filter(x=>!f(k).includes(x)); console.log(m.length+' ключей без казахского'); console.log(m.join('\n'))"
```
>
> В i18n не вынесены данные: статьи новостей (`news.data.ts`) и биографии
> руководителей (`structure.component.ts`). Они остаются русскими на всех языках —
> для их перевода нужны поля по языкам в самих данных.

### Smoke-прогон по живому приложению

`npm run smoke` (`e2e/smoke.mjs`) поднимает dev-сервер на порту 4300, водит по
нему headless-Chromium и проверяет то, чего юнит-тесты не видят: заголовки

```bash
BASE_URL=http://localhost:4200 npm run smoke    # по уже запущенному
```

Браузер ставится отдельно от пакетов: `npx playwright install chromium`.

## Деплой

```bash
npm run build     # → dist/hydro-site/browser
```

Выкладывать нужно **содержимое** `dist/hydro-site/browser/`, а не саму папку и не
`dist/` целиком: рядом с `browser/` лежат `3rdpartylicenses.txt` и
`prerendered-routes.json`, на сервере они не нужны.

В сборку попадает `src/.htaccess` — он и включает SPA-фолбэк. Проверьте, что файл
доехал: без него прямой заход на `/news/3` вернёт 404 от сервера.

### Plesk (hydrogeo.kz)

Корень сайта — `httpdocs`. Порядок обновления:

1. `npm run build` локально.
2. Сделать резервную копию текущего `httpdocs` (в Plesk: «Архив» или
   Инструменты → Резервное копирование).
3. **Очистить `httpdocs`.** Имена чанков содержат хэш, поэтому файлы старой
   сборки не перезаписываются, а копятся: через несколько выкладок в корне
   будут десятки мёртвых `chunk-*.js`.
4. Загрузить содержимое `dist/hydro-site/browser/` — удобнее одним zip и
   распаковать на месте, там ~70 МБ, основное это `assets/`.
5. Убедиться, что `.htaccess` на месте: в файловом менеджере Plesk включите показ
   скрытых файлов, иначе его не видно.
6. Открыть сайт и проверить прямой заход на внутренний адрес, например
   `hydrogeo.kz/contacts` — должна открыться страница, а не ошибка сервера.

### Как проверить, читается ли `.htaccess`

Не гадая и не выкладывая ничего: сайт уже отвечает, достаточно запросить путь,
которого нет.

```bash
for p in /contacts /net-takogo-puti /chunk-NETTAKOGO.js /assets/i18n/net-takogo.json; do
  printf '%-34s %s\n' "$p" "$(curl -so /dev/null -w '%{http_code} %{content_type}' -L "https://www.hydrogeo.kz$p")"
done
```

Как читать ответ:

| Что вернулось | Что это значит |
| --- | --- |
| `/contacts` → `200 text/html` | SPA-фолбэк работает, прямые ссылки открываются |
| `/contacts` → `404` | фолбэка нет: ни `.htaccess`, ни правил в nginx |
| `/chunk-NETTAKOGO.js` → `404` | `.htaccess` из этой сборки читается, правила применились |
| `/chunk-NETTAKOGO.js` → `200 text/html` | `.htaccess` **не** применяется — нужны правила в nginx |

Последняя строка и есть искомая проверка. Фолбэк на несуществующий `.js`
запрещён именно нашим `.htaccess`, поэтому 404 на нём — признак, что Apache
файл прочитал. Тот же запрос стоит повторить сразу после каждой выкладки.

> На момент выкладки этой версии сайт отвечал `200 text/html` на все четыре
> запроса: фолбэк настроен, но не ограничен документами — пропавшие чанки и
> переводы отдаются как HTML.

Если `.htaccess` не читается, те же правила задаются в Plesk в «Настройках
Apache и nginx» (Домены → hydrogeo.kz):

```nginx
location /assets/ {
  try_files $uri =404;
}

location ~* \.(js|css|map|woff2?|ico|png|jpe?g|svg)$ {
  try_files $uri =404;
}

location / {
  try_files $uri $uri/ /index.html;
}
```

Фолбэк обязательно ограничивать документами. Если под него попадут скрипты и
ассеты, пропавший файл вернётся как `index.html` со статусом 200 — а это ломает
навигацию после выкладки: имена чанков хэшируются (`outputHashing: "all"`), и
открытая у пользователя вкладка просит уже несуществующий чанк. Приложение такой
случай обрабатывает само: `withNavigationErrorHandler`
(`src/app/core/chunk-load-error.ts`) перезагружает страницу, чтобы браузер получил
свежий `index.html` — но только если сервер честно ответил 404.

Тексты после выкладки обновляются сами: переводы запрашиваются с версией сборки
в адресе, поэтому чистить кэш браузера посетителям не нужно. Если проверяете
исправление текстов — открывайте сайт **без** жёсткой перезагрузки, иначе
проверка ничего не докажет.

Статуса 404 у неизвестных путей при этом всё равно нет — их отдаёт `index.html` с
кодом 200. Чтобы опечатки в ссылках не попадали в индекс, `NotFoundComponent`
выставляет `<meta name="robots" content="noindex, follow">`.

### Автопубликация новостей из Telegram

Помимо ручной выкладки, раз в 30 минут (или по кнопке «Run workflow» на вкладке
Actions) отрабатывает `.github/workflows/telegram-news.yml`:

1. `scripts/fetch-telegram-news.mjs` тянет `t.me/s/QR_Su_resurstari_ministrligi`
   (публичный канал Министерства водных ресурсов и ирригации РК — не свой канал
   Казгидрогеологии, публикуется без модерации). Без бота и токенов, просто
   HTML-страница веб-превью.
2. Каждый пост канала — отдельная новость сайта; посты, разбитые автором на два
   сообщения по языкам, не склеиваются (риск ложного объединения важнее
   дублирования).
3. Абзацы поста делятся на русский/казахский по казахским буквам
   (`ә ғ қ ң ө ұ ү һ і`). Русский текст переводится на английский через
   LibreTranslate (поднимается в самом workflow, без ключей); казахский не
   переводится никуда — ни LibreTranslate, ни DeepL его не поддерживают.
4. Результат уходит в `src/assets/news/telegram-news.json` (модель
   `NewsItem.title/preview/content/fullContent` — либо строка, либо
   `{ ru?, kz?, en? }`, см. `src/app/models/news.model.ts`), прогресс — в
   `scripts/state.json` (`lastId`). Оба файла коммитятся и пушатся ботом
   `hydrogeo-news-bot`. **Первый запуск не подтягивает историю канала** —
   запоминает текущий последний `id` и публикует только то, что появится после.
5. `TelegramNewsService` (`src/app/core/telegram-news.service.ts`) грузит этот
   JSON во время выполнения и подмешивает записи к `NEWS_DATA`
   (`src/app/models/news.data.ts`) — их показывают и `NewsComponent` (`/news`),
   и виджет трёх последних новостей на главной (`NewsPreviewComponent`).
   У постов без фото в канале стоит плейсхолдер `NEWS_PLACEHOLDER_IMAGE`
   (`assets/images/logo.svg`) — в вёрстке он отрисован маленьким по центру,
   а не растянут на всю карточку.

**Нужные секреты репозитория** (Settings → Secrets and variables → Actions):
`FTP_HOST`, `FTP_USERNAME`, `FTP_PASSWORD` — доступ к hydrogeo.kz на Plesk.
Отдельно там же Settings → Actions → General → Workflow permissions должно
быть выставлено «Read and write permissions» — иначе workflow не сможет
закоммитить обновлённый `telegram-news.json` обратно в репозиторий.

**Доставка на хостинг пока не работает.** Обычный FTP (пассивный режим) рвётся
с `ECONNRESET` на data-socket при заливке с раннеров GitHub Actions — похоже,
файрвол хостинга не пропускает соединение на выданный сервером порт. SFTP для
дополнительной FTP-учётки (`kz_site`, домашняя папка `/httpdocs`) тоже не
работает — соединение обрывается сразу после логина, похоже, у неё просто нет
SSH-доступа. Пока идёт переписка с поддержкой хостинга (или проверка доступа
владельца подписки), шаг деплоя в workflow может падать — это ожидаемо и не
означает, что сломался сбор новостей: коммит с новым `telegram-news.json` всё
равно долетает до репозитория, и попадёт на сайт при следующей обычной ручной
выкладке (см. «Деплой» выше) — файл лежит в `src/assets/`, значит соберётся
в `dist/` сам, отдельно готовить ничего не нужно.

**Проверить руками** (без ожидания cron):

1. GitHub → вкладка **Actions** → workflow **«Telegram news»** → **Run workflow**.
2. Зелёная галка = сбор/коммит отработали (доставка на хостинг могла быть
   пропущена, если новых постов не было, либо упасть — см. выше).
3. Смотреть `src/assets/news/telegram-news.json` в репозитории или коммиты
   `Автообновление новостей из Telegram-канала`.

**Протестировать локально, не трогая прод:** временно занизить `lastId` в
`scripts/state.json`, прогнать `node scripts/fetch-telegram-news.mjs` — скрипт
заберёт реальные посты канала как «новые» и запишет в
`src/assets/news/telegram-news.json`. После проверки — `git checkout --
src/assets/news/telegram-news.json scripts/state.json`, чтобы тестовый бэкфилл
не попал в реальный коммит.

## Заметки

- В `package.json` объявлены, но нигде в `src/` не используются: `primeng`,
  `primeicons`, `@angular/cdk`, `@angular/animations`, `@angular/forms`,
  `tailwindcss` (конфига Tailwind в проекте тоже нет). Их можно удалить.
- Новости частично статические (`src/app/models/news.data.ts`, без бэкенда),
  частично — автопубликация из Telegram-канала, см. раздел выше.
